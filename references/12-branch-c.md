# 12 C 分支：自建 U-Boot / 内核（入口）

> **本 skill 不展开这一支。** 这里只写"什么时候该考虑、要考虑什么、去哪找资料"。
> 原因很简单：多数板子可以借同族镜像的 bootloader，只换 dtb；自建引导是少数派，
> 而且强依赖具体 SoC、具体 DDR 颗粒、具体工具链版本，写成通用手册容易误导。

## 1 什么时候该考虑

满足任意一条：

- **P3/P5 首启在 U-Boot 之前就死**（串口完全没有输出，或 DDR 初始化失败）；
- 镜像自带的 bootloader 与本板 DDR 参数不匹配，反复训练失败；
- 主线没有本板必需的外设驱动，且只能通过改内核解决；
- 需要板子做不到的存储模式（例如只有 HS200 证据却要 HS400ES），且确认值得。

先排除这些再考虑自建：

- 串口本身没问题？（电平、波特率、终端）
- 是不是只是 dtb 的串口/时钟写错？
- 有没有同族板/同厂的 bootloader 可以直接复用（逐字节相同即可）？

## 2 要考虑什么

| 项 | 要确认的事 |
|---|---|
| **SoC 与 DDR** | DDR 颗粒型号、频率、容量、CS 数；厂端跑多少 MHz |
| **BL31（ATF）** | 版本、与 DDR blob 的搭配 |
| **DDR blob** | 来源（厂商/上游 rkbin）、版本、频率；不同频率可能要重新训练 |
| **U-Boot 配置** | defconfig、调试串口基地址与波特率、是否需要网口/USB |
| **烧写布局** | idbloader 与 u-boot.itb 的 LBA、GPT 起始位置 |
| **不要混用** | 发行版自带的引导文件与自编主线 U-Boot 不是一回事，混用会出格式/地址问题 |
| **内核缺口** | 需要哪些 config、哪些驱动、是否有主线 binding |

## 3 去哪找资料

- SoC 厂商的官方 U-Boot 与 rkbin 仓库（DDR/BL31 blob）；
- 上游 U-Boot 的 `configs/*_defconfig` 与 `doc/board/`；
- 同 SoC 其他板的 defconfig 与 dts；
- 内核 `Documentation/devicetree/bindings/`；
- 发行版（Armbian/ophub）里已有的同族引导文件，先比对再决定是否自建。

## 4 风险

- **DDR 频率**：厂端可能只跑一个保守频率，上游 blob 默认更高；裕量未知，起不来要降频。
- **工具链**：交叉编译器版本会影响内核模块结构，自编内核可能"vermagic 相同却载不进模块"。
- **时间**：2~5 天起步，且失败时没有明确的止损点。
- **回报**：多数情况下，收益只是"少依赖一个厂端文件"。

## 5 建议

1. 先把"借 bootloader + 只换 dtb"这条路走到尽头（换镜像、换介质、换版本）。
2. 确认失败点确实在引导阶段，而不是 dtb。
3. 如果决定自建，**单独开一个阶段**，不要和 P4 混在一起。
4. 自建成功后，把配置与 blob 版本记录下来，写进 board-profile 与 release 说明。

## 6 本 skill 的边界

- 不提供具体 defconfig、DDR 参数、烧写命令；
- 不判断"要不要自建"——由人和 agent 根据 P3/P5 的证据一起决定；
- 自建成功后，后续的 DTS 工作仍然回到 P4，用同一套流程。
