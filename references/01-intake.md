# 01 接板问诊

> 目标：在动手之前，用尽量少的提问，把"这块板是什么、能不能做、做到哪"弄清楚。
> 产出是一份 `templates/board-profile.md`。

## 原则

1. **一次问 3~5 个**，不要一口气抛出全部清单。用户答不上来的，标"未确认"，不要替他猜。
2. **先问物理事实，再问意愿**：板子是什么，比"你想做到什么程度"更容易回答，也更能建立信任。
3. **每个答案都要能落到"从哪看到的"**：照片、丝印、`dmesg`、串口日志、规格书。
4. **不问 agent 能自己查的**：主线支持、binding、同族板，这些去查，不要占用用户的耐心。

## 十二项事实

| # | 项 | 为什么需要 | 怎么拿到 | 默认证据级别 |
|---|---|---|---|---|
| 1 | 板卡身份（丝印/型号/批次） | 同名板可能多批次，料不同 | 正反面照片、板边丝印 | L4→L3 |
| 2 | SoC 具体型号 | 决定主线支持与 dtsi | 丝印、`/proc/cpuinfo`、`dmesg` | L2 |
| 3 | 内存容量与颗粒 | 决定 dts 的 memory 节点与 DDR 参数 | 丝印、`dmesg` 的 DDR 打印 | L2 |
| 4 | 存储：eMMC / SD / SPI NOR | 决定能不能"拔卡即回滚" | 照片、分区表、`lsblk` | L2 |
| 5 | 原厂系统与内核版本 | 决定取证手段（Android 还是 Linux） | 设置页、`uname -a`、串口日志 | L2 |
| 6 | 是否能 root / adb | 决定能不能运行时取证 | 试 `adb root`、串口 `id` | L2 |
| 7 | 调试串口：位置/电平/波特率 | 唯一的"眼睛" | 照片 + 实际接线 + 日志 | L1/L2 |
| 8 | MaskROM：按键位置 + USB 口 | 救砖通路 | 照片、实测进模式 | L1 |
| 9 | 网络：有无网口、当前 IP | TFTP/SSH 的前提 | `ip a`、实际 ping | L2 |
| 10 | 显示：HDMI/DSI/edp | 第二条眼睛；也是外设清单 | 照片、实际输出 | L1/L2 |
| 11 | 备份手段与空间 | P5 的准入券 | 读 flash 工具、备份盘 | L2 |
| 12 | 目标：Lite 还是 Full；哪些外设必须有 | 决定范围与工期 | 直接问 | — |

## 可行性判定

打完分再决定，不要凭感觉。

| 维度 | 好（2） | 一般（1） | 差（0） |
|---|---|---|---|
| 主线 SoC 支持 | 同 SoC 有成熟 dts | 只有 SoC dtsi | 无主线支持 |
| 可回退介质 | 有 TF 卡槽 | 有 USB/TFTP 可用 | 只有 eMMC |
| 观测通道 | 串口已引出且能登录 | 有测试点可焊 | 找不到串口 |
| 救砖通路 | MaskROM + loader 可用 | 只有 MaskROM | 都不确定 |
| 厂端 DTB | 能拿到活 dtb | 只能从 boot.img 抠 | 拿不到 |
| 参考板 | 同厂/同族有可启动 dts | 只有 SoC 公版 | 无 |

- **10~12 分**：正常推进。
- **6~9 分**：条件 go，先补短板（通常是串口或备份），并把短板写成风险。
- **0~5 分**：不建议开工。明确告诉用户"现在做，风险大于收益"，给出补条件的建议。

## 怎么教用户采集

用户不是传感器，需要具体指令。给"手怎么放"级别的动作。

### 拍照清单

- 正面全景、背面全景（能看清丝印）
- 主控、内存、eMMC、PMIC、PHY、WiFi 模块、音频芯片（各一张微距）
- 接口：串口针脚、MaskROM 按键、USB 口、网口、HDMI、DC 座
- 分区表截图（如果能进 MaskROM 工具）

> 拆不动散热片就别拆，用运行时信息补。不要为了拍照损坏板子。

### 串口接线

1. 找 4 pin（或 3 pin）排针，常见丝印 `UART`、`DEBUG`、`CON`。
2. 确认电平：万用表量 TX 空闲电压。**负压说明板上已做 RS-232 转换，必须用 USB-RS232，不能用 USB-TTL。**
3. 接线：TX↔RX 交叉，GND 共地，先不接 VCC。
4. 波特率先试厂端值（常见 1500000，其次 115200），**先开终端再上电**。

### MaskROM

1. 断电。
2. 按住按键（或短接测试点）。
3. 上电，保持按住 2~3 秒。
4. 电脑端看到 `Maskrom` 设备即成功；看不到就换 USB 口/换线再试。

## 首次对话脚本

可以照这个顺序开场（按用户语言调整）：

```
在动手前，我需要先弄清楚 5 件事：
1. 板子的 SoC 具体型号是什么？丝印或 /proc/cpuinfo 都行。
2. 存储是 eMMC 还是 SD？有没有 TF 卡槽？
3. 串口现在能登录吗？波特率多少？COM 口号是多少？
4. MaskROM 按键在哪、用哪个 USB 口？
5. 原厂系统能备份吗？备份盘有多大？

先回答你知道的，不知道的写"不清楚"，我来教你怎么确认。
```

## 产出

把答案填进 `templates/board-profile.md`，每行写清"值 / 证据级别 / 出处 / 状态"。
这份文件之后会被反复引用：DTS 的每个取值都要能追回某一行。

## 常见错误

- 用户说"应该是 RK3568"，就当成确定事实——去看丝印或 `dmesg`。
- 把"同型号"当成"同硬件"：同名板可能换过 PHY、WiFi 模块、codec、DDR 封装。
- 没确认串口电平就接线，烧掉转换器。
- 没确认备份就答应"先刷一版试试"。
