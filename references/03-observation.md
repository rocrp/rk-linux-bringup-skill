# 03 观测通道

> **这是最容易被跳过、又最贵的一步。** 没有观测通道时，任何失败只能得到"起不来"三个字；
> 有了它，同一个失败能给出错误码、设备树状态、寄存器值。

## 1 四条通道

| 通道 | 何时可用 | 能回答什么 | 独立性 |
|---|---|---|---|
| **串口** | 从 DDR 第一条打印开始 | 启动链每一步、内核 panic、shell | 主通道 |
| **画面（HDMI）** | 内核有 framebuffer/DRM 后 | 是否真的显示、分辨率、EDID | 与串口独立 |
| **SSH** | 系统起来且网络通 | 批量取证、回归、压测 | 依赖网络 |
| **静态** | 任何时候（离线） | 镜像里有什么、分区、dtb | 完全离线 |

**至少要有两条独立通道**，互为兜底。

## 2 串口

### 2.1 先确认电平

用万用表量 TX 对 GND 的空闲电压：

- **3.3 V / 5 V 正压** → TTL，用 USB-TTL（注意 3.3 V/5 V 选择）。
- **负压（如 −5 V 左右）** → 板上有 RS-232 转换芯片，**必须用 USB-RS232**；
  用 USB-TTL 可能打坏转换器。

接线：TX↔RX 交叉、GND 共地、先不接 VCC（除非确认板子需要）。

### 2.2 再确认波特率

- 先试厂端值：RK 平台常见 `1500000 8N1`，其次是 `115200`。
- 如果输出是乱码，通常是波特率不对；完全无输出则先查接线与电平。
- 有的板子 U-Boot 阶段一个波特率、内核阶段另一个，要分别试。

### 2.3 顺序：先开终端，再上电

启动信息只在上电最初几秒。先连好终端、开始记录，再给板子上电。
反过来做，往往会错过 DDR 和 U-Boot 的版本串，而那两行是判断"引导链走到哪"的关键。

### 2.4 端口独占

同一个 COM 口同一时刻只能被一个程序打开。用脚本抓日志前，先让人关掉串口助手；
否则脚本报"访问被拒绝"，而人以为是线的问题。

### 2.5 抓日志

要求：

- **原始字节落盘**（不要只存解码后的文本，避免编码问题）；
- 带时间戳或至少记录开始/结束时间；
- 固定时长后自动退出（避免忘记停）；
- 能被动监听，也能按脚本逐行发命令。

`scripts/serial/capture-boot.ps1` 是纯监听，`scripts/serial/serial-console.ps1` 是可交互版
（支持 `!raw=`、`!spam=`、`!wait=` 等指令）。

## 3 画面

- 用 HDMI 采集卡最省事：能看到画面、也能录屏回放。
- 没有采集卡就用"屏幕 + 拍照"，但**不要用截图代替全文日志**。
- **黑屏 ≠ 没启动**：内核 DRM 驱动如果是模块、又没有 simpledrm，framebuffer 可能只在
  initramfs 阶段存在，之后就没输出了。
- 判断"是不是真的显示"要看 EDID：`connected` 但 EDID 为 0 字节，往往是固定模式输出，不是真识别。

## 4 SSH

系统起来后，SSH 比串口更适合批量取证：

```sh
ssh root@<ip> 'dmesg -l err; lsusb -t; ip -br a; cat /proc/device-tree/model'
```

注意：

- 设备端 rootfs 可能是 `commit=600`，写完不 `sync` 就断电会丢文件；
- 首次登录可能要设密码/改主机名，脚本要能处理交互；
- 网络没通之前不要依赖它。

## 5 静态通道

在开发机上直接读镜像：

- 解析 GPT/分区表；
- 从 `boot` 分区里取 `Image`、`uInitrd`、`config`、dtb；
- 读 `armbianEnv.txt` / `boot.scr`；
- 解析 ext4（只读）。

这条通道不需要板子在线，适合在等待硬件时推进。

## 6 失败模式速查

| 现象 | 先查 | 不要先做 |
|---|---|---|
| 完全无输出 | 电平、接线、波特率、终端是否先开 | 怀疑内核/换 dtb |
| 乱码 | 波特率 | 换线 |
| U-Boot 有、`Starting kernel` 后静默 | cmdline 的 `console=`、`loglevel`、`earlycon` | 改 UART 引脚 |
| 只有前几行就停 | 供电、DDR 初始化 | 改 dts |
| 串口能收不能发 | TX 线、地线、端口占用 | 换板子 |
| 画面黑但串口正常 | framebuffer/DRM 是否加载 | 判定"没启动" |

## 7 记录纪律

- 每次启动都留一份**原始串口日志**，命名带日期与 dtb 版本。
- 日志里至少要有：DDR 版本串、U-Boot 版本串、`Machine model`、内核版本、最后一个 `login:`。
- 关键片段粘进 session log，全文放证据目录。
- **不要用截图代替全文**：截断的日志会让推理建立在错误前提上。
