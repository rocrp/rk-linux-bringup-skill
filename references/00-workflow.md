# 00 阶段机：P0–P6

> 这篇是总表。每阶段的详细操作在对应专题里，这里只回答"按什么顺序、每步的入口和出口是什么"。

## 0 开工前提：独立目录 + 四件套

在进入 P0 实操之前，先把"容器"建好：

- **一块板一个独立目录**（`<board>-bringup/`），不与别的板子共用；
- 顶层必须有 `board-profile.md`、`feasibility.md`、`plan.md`、`progress.md` 和 `logs/`；
- `plan.md` 必须由人确认定稿后冻结，之后改动要人批准。

这是强制的，理由与细则见 `13-workspace.md`。**目录和文档不齐，不许开工。**

## 为什么分阶段

顺序不是按功能清单排的，而是按**风险**和**依赖**排的：

- 越靠近电源和启动，方差越大，越要先做、越要留退路；
- 后一项依赖前一项的事实：没拿到厂端 DTB，写 DTS 就是猜；
- 每个阶段有可验证的门槛，避免把"未验证"带进下一步。

一条经验：**先降不确定性，再降改动成本，最后才改代码。**

|---|---|---|---|---|---|---|

## 逐阶段

### P0 立项

**目的**：决定做不做、做到哪，并把"失败怎么退"写下来。

**动作**

1. 问诊（见 `01-intake.md`），把已知事实写进 `board-profile.md`。
2. 写两级成功定义：**最小可用**（能启动、网络、存储、稳定）与**完整可用**（显示、无线、音频、RTC、按键）。
3. 写**"明确不做"清单**，每条带理由（主线无驱动 / 需要自写驱动 / 收益低 / 无法验证）。
4. 选路线：换厂端 dtb（跨代基本不可行）/ 借同族镜像 + 自写板级 dts / 自建引导 / 回到原厂系统。
   选成本最低且可回退的那条，其余写成预案。
5. 找"失败就整体失败"的环节，设为第一道门槛（通常是有没有可回退介质、能不能进 MaskROM）。

**G0 判据**

- 失败时能回到原厂状态（备份 + MaskROM/loader）；
- 有一条"不碰 eMMC 就能验证大半东西"的路径；
- "明确不做"写下来了；
- 每阶段的"算过"标准可验证；
- 最坏情况的退路成本估过。

**反模式**：把"能不能做"写成"怎么做"；不写不做清单，最后被屏参/摄像头拖死；
用"同型号"代替批次核对。

### P1 取证

**目的**：把未知的料号、总线、引脚，一次性变成"有出处的事实"，并建立唯一退路。

**动作**（详细命令见 `02-evidence.md`）

1. 实物拍照：丝印、接口位号、关键芯片。
2. 提厂端 DTB：活 dtb（`/sys/firmware/fdt`）或 `boot.img` 内嵌 dtb，两条路互补。
3. 运行时取证：`dmesg`、`/sys`、i2c、gpio、regulator、USB、mmc 时序。
4. 活 DTB 与厂端 DTB 做节点级 diff，区分"板级事实"与"bootloader 运行时补丁"。
5. 备份：分区/系统区、loader、分区表；验证备份可读。
6. 建"已知良好参照物"：一份能启动的同族镜像 + 它的 dtb/env/config。

**G1 判据**

- 任一引脚/总线问题都能回答"我从哪看到的"；
- 备份的 sha256 记录在案，抽查可读；
- loader 可用，能进 MaskROM。

**反模式**：拿规格书当接线事实；拿"万能固件"里的节点当板上真有；不备份就动 eMMC。

### P2 观测

**目的**：造出两条独立的"眼睛"，让后面的每次失败都能给出错误码而不是"起不来"。

**动作**：串口（先确认电平，再确认波特率，**先开终端再上电**）+ 画面（采集卡或拍照）。
起来之后 SSH 是第三条通道；离线读改镜像是第四条。

**G2 判据**：能从 DDR 第一行抓到 `login:`，全程不需要键盘；串口坏了还有画面兜底。

**反模式**：把"没输出"直接归因到硬件；观测通道没通就开始改 DTS；用截图代替全文。

### P3 点亮

**目的**：在**完全不写 eMMC** 的前提下，回答"主线内核能不能在本板起来"。

**动作**

1. 选底料镜像：先定内核版本门槛，再选最像的机型。
2. 取镜像内的 `Image` / `uInitrd` / config（能不自编就不自编）。
3. 写首版最小 dtb：只开串口、电源、存储、网口、USB，其他全 disabled。
4. 选零写入路线：TF 卡 / TFTP 内存直启 / USB rootfs（见 `04-boot.md`）。
5. 按 L1~L4 阶梯记录，每级都留串口原文 + dtb sha256。

**G3 判据**：串口可登录 + PMIC 全注册 + 存储认盘且顺序读无错 + 网口链路正常。

**反模式**：一次改多个变量；没有日志就连续刷机；把"换了 dtb 没变化"当成"dtb 没用"。

### P4 外设

**目的**：产出"能当节点用"的硬件部分。

**动作**：按依赖链（电源 → 存储 → 调试串口 → 网络 → USB → 显示 → 无线/音频/RTC/LED），
**一次只改一类**：改 → 编译 → 投放 → 重启 → 验收 → 记录 → 下一类。

**G4 判据**：核心集全通；按需项逐项"通过/明确放弃/待后续"；发布版 dts 冻结。

**反模式**：抄参考板的电源使能脚；把"兼容板能用"当成"本板能用"；一次改多类。

### P5 固化

**目的**：从"我的卡能跑"到"谁刷都能跑"。

**动作**

1. 写前复核：备份可读、loader 可用、发布版 dtb、镜像身份、回滚步骤。
2. 装配镜像：投 dtb、改 `fdtfile`、处理首启扩容开关。
3. 写盘、冷启动 ≥3 次、复测关键外设、稳定性观察。
4. 出四件套：`.img` + `.xz` + `.sha256` + 说明。

**G5 判据**：从目标介质**断电冷启动 3/3** 进系统；关键外设复测通过；稳定观察期内无掉盘/断网/新增错误。

> **软重启不算冷启动。** 断电 ≥10 s 再上电才算。

**反模式**：拿"第一次成功"当稳定；忽略首启脚本改了持久状态；忘记 `sync`。

### P6 上游（可选）

**目的**：让别人也能用。

**动作**：把 dts 整理成主线风格（删注释、换名、只留 SPDX + 几行说明）→ 提 issue（设备信息、
验证矩阵、已知限制）→ 按维护者要求拆 PR（内核 dts / 引导 / 发行版配置）→ 合并。

**G6 判据**：PR 合并，或维护者明确不收且理由记录在案。

详见 `08-upstream.md`。

## 可选模块

### P1.5 在役机基线

**触发条件**：板子已经跑着"别人给的"系统，且不能拔卡即回滚。

**要做的三件事**：备份 `/boot` 与在役 dtb 作为 golden；修 DNS（悬空软链）；修 `ping` 权限与时钟同步。
这三件看起来与适配无关，但不修就没法 `apt`、没法取证。

**门槛（G1.5）**：`getent hosts` 有 A 记录；`curl` 不带 `-k` 能通；时间同步正常；普通用户能 `ping`。

### C 分支：自建 U-Boot / 内核

**触发条件**：P3 或 P5 首启在引导阶段就死（DDR/loader 不匹配），或主线缺本板必需驱动。

**本 skill 只给入口**，见 `12-branch-c.md`。

## 预算与方差

| 阶段 | 预算 | 方差 | 备注 |
|---|---|---|---|
| P0 | 0.5 d | 低 | 不写"不做清单"会在这里埋雷 |
| P1 | 0.5~1 d | 中 | 等器件/等资料；等待期做正交实验 |
| P2 | 0.5 d | 低，但漏了会放大后面所有阶段 | 与 P1 并行 |
| P3 | 1~3 d | **最高** | 留 2 倍缓冲 |
| P4 | 1~3 d | 中 | P1 越扎实越快 |
| P5 | 0.5~1 d | 低 | 断言写全 |
| P6 | 0.5~1 d | 低 | 先问规则，再做最后回归 |

**总预期**：一块陌生板 5~9 个工作日；有同族参考、有 TF 卡槽会明显更快。

## 产物链（断了就会返工）

```
厂端 live.dts ──► P4 的取值依据 ──► 每版 dtb
原厂串口日志（版本串） ──► P3 的判据（版本串一变，说明借到了 bootloader）
备份 + loader ──► P5 的准入券（缺一不许写）
镜像底料身份 + Image/uInitrd sha256 ──► P5 装配、P6 复现
每版 dtb 的 sha256 ──► 投放脚本的断言
dmesg -l err 基线条数 ──► 之后每版"零新增"的判据
每版串口日志 ──► 变更说明的"现象"列 ──► PR 的验证矩阵
```

## 角色

| 标记 | 谁 | 典型动作 |
|---|---|---|
| `[人]` | 用户 | 断电上电、插卡、刷机、按 MaskROM、量电压、焊接、听、看、拍板、对外提交 |
| `[机]` | agent（开发机） | 读日志、反编译、写 DTS/脚本、编译、比对、写文档、备料 |
| `[设备]` | 设备端 | 命令由人执行；授权后 agent 可做只读诊断 |

## 常见偏离

1. **跳过 P2**：省半天，后面每次失败都要多花一天。
2. **P1 不备份**：等想回滚时才发现没有底片。
3. **P4 并行改**：失败后无法二分，靠猜。
4. **P5 只看一次冷启动**：首启脚本改了持久状态，第二次就挂。
5. **P6 用"我测过"代替证据**：维护者要的是日志与回归，不是结论。
