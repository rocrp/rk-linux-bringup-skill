# 09 排障

> 排障的第一原则：**先分层，再动手**。越靠左越贵、越该先排除。

## 1 分层

```
物理层 → 供电/复位 → 时钟 → 总线(i2c/spi/mmc) → 驱动 probe → 子系统框架 → 用户态配置
```

经验顺序：**物理层 → 电源 → 总线 → 驱动 → 配置**。

一次只验证一层；跨层同时改，等于放弃二分。

## 2 症状 → 第一动作

| 症状 | 先查 | 不要先做 |
|---|---|---|
| 上电零输出 | 串口电平、TX 空闲电压、波特率、终端是否先开 | 换 dtb、怀疑内核 |
| 有 U-Boot，`Starting kernel` 后静默 | bootargs 的 `console=` 顺序、`loglevel`、`earlycon` 时钟 | 改 UART 引脚 |
| BL31 之后、U-Boot 之前死 | 复位/电源域；先断电冷启动 | 改 dts |
| 内核起来但 rootfs 挂不上 | `/proc/partitions` 有没有块设备 | 直接改 `root=` |
| 有分区但挂不上 | `root=` 语法、PARTUUID/UUID、initramfs 是否可用 | 重刷镜像 |
| 挂上了但不是根 | `findmnt /` 与分区表比对 | — |
| 设备节点在、功能不对 | 供电/使能脚/极性/时序 | 改驱动 |
| 吞吐/CRC 异常 | 物理层（线/卡/触点）→ 时序 → 供电 | 加延迟参数 |
| 第二次启动才失败 | 首启脚本改了持久状态（分区表/配置） | 换镜像 |
| 偶发 probe 失败 | 上电时序、依赖注册顺序 | 改 dts 猜 |

## 3 常见的"假根因"

| 看起来像 | 实际 | 教训 |
|---|---|---|
| 根 hub 全枚举 ⇒ USB 供电正常 | VBUS 可能 0 V；hub 枚举不需要 VBUS | 枚举 ≠ 供电 |
| `connected`/`enabled` ⇒ 接了屏 | EDID 可能 0 字节 | 状态 ≠ 画面 |
| dmesg 里 N 条错误 ⇒ N 个问题 | 环形缓冲 + `callbacks suppressed`，计数是下限 | 计数 ≠ 真值 |
| 换个现成 dtb 就好 | 扫遍镜像里的 dtb 可能没有一个满足条件 | 现成 ≠ 适配 |
| 加了参数就好 | 参数可能根本没进 cmdline | 改了 ≠ 生效 |
| 第一次启动成功 ⇒ 镜像没问题 | 首启可能改了分区 GUID | 一次 ≠ 稳定 |
| 同型号 ⇒ 同硬件 | 同名板可能换过料 | 型号 ≠ 批次 |
| 规格书 ⇒ 板上有 | 规格书宣称 11ac，实物只有 2.4G | 文档 ≠ 实物 |
| 厂端 DTB ⇒ 板上有 | 厂端节点可能对应未贴片器件 | 固件 ≠ 实物 |
| 能 ping ⇒ 千兆没问题 | 要跑大流量双向校验 | 连通 ≠ 通路 |

## 4 归因三问

1. 这次**只**变了什么？（没变的东西不要重新怀疑）
2. 手上的证据是哪一级？（L1 物理量 > L2 运行时 > L3 固件 > L4 文档 > L5 传闻）
3. 有没有一条更便宜的证伪实验？（一条 U-Boot 命令 > 一次刷机）

三个答案都清楚时再动手；任何一个答不上来，就回 P1 补取证或回 P2 补观测。

## 5 降成本的实验阶梯

同一件事有四种改法，成本差一个数量级：

1. 改**内存里的 dtb**（U-Boot `fdt set/rm` + `booti`）——一条命令；
2. 改**设备上的 dtb/dts**（板载 `dtc`，一次重启）；
3. **等长覆盖**镜像里的文件（不动元数据，一次刷卡）；
4. 重建镜像/重编内核（最贵）。

先把实验挪到最便宜的那一级，再开始试。

## 6 什么时候该停

- 同一路径**连续 3 次失败** → 换假设或换观测手段。
- 主线确实没有驱动 → 写进"不做清单"；不是核心需求就别现场开发。
- 需要动 eMMC/引导区才能继续 → 先确认备份与救砖通路，并由人执行。
- 偶发、无法稳定复现 → 记为观察项，不要为它改 dts。
- 时间成本已经超过收益 → 明确收口，把现状写进"已知限制"。

## 7 排障记录

- 现象、判断、试过的替代方案都写进日志——失败记录比成功记录更值钱。
- 每次结论标"已验证/推断/未验证"。
- 记录"当时的环境"：哪个 dtb、哪个内核、哪次冷启动。
