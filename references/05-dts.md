# 05 DTS 工作法

> 目标：把一个外设从"知道板上有"变成"节点写对、驱动 probe、功能可用"，并且每一版都能回退。

## 1 三个概念

| 名词 | 是什么 | 谁用 |
|---|---|---|
| **dts** | 文本源码，描述板级硬件 | 人写 |
| **dtb** | dts 编译后的二进制，内核读它发现硬件 | 内核 |
| **dtc** | 编译器：dts → dtb；也能反编译 dtb → dts | 工具 |

ARM 没有 x86 那种自动枚举，**dtb 就是硬件清单**：有哪些设备、接在哪个总线地址、
用哪些引脚、哪个时钟、哪路电源、复位怎么拉。

**dtb 不通用**：每块板走线不同。厂端 dtb 不能直接给主线用，主线同 SoC 公版 dtb 也不认本板外设。

## 2 骨架从哪来（按优先级）

| 来源 | 适用 | 优点 | 风险 |
|---|---|---|---|
| **① 反编译"实测可启动"的 dtb** | 首选：厂端 dtb 能启动，或已有一版能跑的 dtb | 最稳，等价性可证 | 反编译源带 lint 警告；要 `dtc -@` 才有 `__symbols__` |
| **② 上游同代最接近的板级 dts** | 准备上游化，或厂端 dtb 不可用 | 主线风格、可直接提交 | 与厂端事实有差，必须逐块对账 |
| **③ 旧 BSP 的展开版 dts** | **不要用** | 看起来省事 | 代差会静默降级（节点命名、缓存节点都对不上） |

两条策略：

- **减法**：厂端 dtb 是"万能固件"（多套屏参、多个 codec、未贴片器件），从可启动 dtb 出发，
  删掉本板没有的节点，再与 golden 做节点级 diff，确认"只删了该删的"。
- **加法**：以同 SoC 公版 dts 为骨架，按厂端事实逐块改。**凡厂端与参考板取值不同的一律按厂端；
  厂端没写的按参考板 + 主线惯例。** 结果应该是"没有凭空新增节点"，这本身就是一条自检。

## 3 节点推导七步

以一个外设为例：

1. **存在性**：丝印、照片、规格书、`lsusb`/`lsblk`/`dmesg` 确认板上有这个东西。
2. **实例与地址**：厂端 `dmesg` 与 live.dts 给出总线号、地址、中断。
3. **引脚/极性/复用**：厂端 dtb + 运行时 gpio dump + 同芯片板 dts，**三源互证**。
4. **供电与复位**：哪路 regulator 供它、复位脚是谁、什么时候拉。**写在哪个节点上由启动链决定**。
5. **抄骨架**：从三种来源里选一个，先把节点结构写对。
6. **单变量投放 + 分级验收**：一次只开一个外设。
7. **回写**：变更说明一节 + 与厂端对账表一行 + `dmesg -l err` 是否新增。

### 四个卡口

- **"厂端有节点" ≠ "板上焊了"**：厂端 dtb 可能挂着未贴片的器件。用丝印/照片/实测排除。
- **"参考板这么写" ≠ "本板这么写"**：PMIC 挂哪条 i2c、中断脚、USB 5V 使能脚、极性，都可能不同。
- **"主线写法" ≠ "能用的写法"**：有些复位必须在控制器节点上做（驱动在枚举设备前就要拉），
  写到子节点上会形成"先认到设备才能申请 GPIO"的死锁。
- **"厂端写了、参考板没写"的属性，往往正是本板启动链欠的那一段**：判断要不要抄，先问
  "这件事在我的启动链上由谁负责"。

## 4 属性清单（最常错的几类）

| 类别 | 常见属性 | 易错点 |
|---|---|---|
| 开关 | `status = "okay"/"disabled"` | 忘了关掉不用的控制器，导致抢引脚/延迟 probe |
| 引脚 | `pinctrl-0/1`、`pinctrl-names` | 复用功能选错；默认 pinmux 占了别的脚 |
| 供电 | `*-supply`、`regulator-min/max-microvolt` | 电压范围写错；固定轨被当成可调 |
| 复位 | `reset-gpios`、`snps,reset-gpio`、`reset-delays-us` | 极性反；该在控制器节点却写到子节点 |
| 时钟 | `clocks`、`clock-names`、`assigned-clock-parents`、`assigned-clock-rates` | 父时钟没写全，mux 继承 bootloader 残留值 |
| GPIO | `*-gpios`、`gpio-hog` | hog 在部分内核不生效；极性用 `GPIO_ACTIVE_LOW` |
| 中断 | `interrupt-parent`、`interrupts` | 中断脚被别的控制器占用 |
| 总线 | `bus-width`、`max-frequency`、`non-removable` | 声明了板子做不到的速率/电压 |

## 5 编译

推荐不依赖 `make`，直接用 `cpp` 展开 + `dtc` 编译（在 Linux/WSL 里）：

```bash
cpp -nostdinc -I include -I arch/arm64/boot/dts \
    -undef -D__DTS__ -x assembler-with-cpp \
    board.dts -o board.pre.dts

dtc -@ -I dts -O dtb -o board.dtb board.pre.dts
```

要点：

- `-@` 生成 `__symbols__`，overlay 和部分工具需要它。
- include 路径要指向**与目标内核同版本**的源码树；代差会静默改节点。
- 编译后自检：`fdtget board.dtb / model`、`compatible`、符号数、关键节点 `status`。
- 警告要看来源：反编译源天然带 lint 警告，先确认"基线也报"再忽略。

`scripts/dtb/dts2dtb.sh` 封装了这条流水线。

## 6 版本与命名

- **只增不改**：每次大改 `v1`→`v2`，微调 `v2_1`；旧版保留，随时能回。
- 设备端文件名与仓库一致，避免"不知道跑的是哪版"。
- 每版记录：dtb 大小、sha256、`__symbols__` 数、`model`、`compatible`。
- 变更说明每版一节：改了什么 / 依据 / 现象。

## 7 diff

| 工具 | 用途 |
|---|---|
| 整树 diff | 快速看"哪些节点/属性不同"，适合小改动 |
| **语义 diff** | 先把 phandle 解析成节点路径再比，只换编号不算差异；适合判断"两版是否等价" |
| 功能级对账 | 按外设列表比对"开关状态 + 关键属性"，适合大板子，避免被整树噪声淹没 |

用语义 diff 判"源码 dtb 与在役 dtb 是否等价"；用整树 diff 找"这一版到底改了什么"。

## 8 提交版整理

上游只接受主线风格：

- `#include "rk3xxx.dtsi"` + 板级覆盖，而不是几千行展开版；
- 只留 SPDX + 几行板级说明，删掉调试注释；
- `model` / `compatible` 用正式名称；
- 用上游当天 HEAD 的头文件编译，确认没有新增 warning。

可以用脚本做"删注释 + 换名"，但要**断言输出代码流与源文件一致**（只删注释不应改变 dtb）。

## 9 反模式

- 一次改多类外设，失败无法二分。
- 抄参考板的电源使能脚，结果口子没电。
- 拿"兼容板能用"当"本板能用"。
- 把"改了没生效"当成"改了没用"——先回读确认参数真的进去了。
- 在没接串口的情况下连续改 dts 试。
