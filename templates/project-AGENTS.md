# 项目规则（给 agent 用）

> 复制到你的适配工作区根目录，命名为 `AGENTS.md`（或该 agent 约定的规则文件名）。
> 它管"怎么做"，`SKILL.md` 管"做什么"。

## 0 工作目录与文档（强制）

- 一块板一个独立目录（`<board>-bringup/`），不与别的板子共用；完成后归档，不清空复用。
- 顶层必须有：`board-profile.md`、`feasibility.md`、`plan.md`、`progress.md`、`logs/`。
- `plan.md` 先出草案，用户确认后定稿并冻结；之后改动需用户提出或批准，并在修订记录留一行。
- `progress.md` 只写"当前位置 + 每小阶段状态 + 会话索引"，不写命令/数字/路径/现象。
- 会话日志 `logs/session-NN-<phase>.md`，一个对话一份，序号补零；已结束的只增不改。

细则见 skill 的 `references/13-workspace.md`。

## 1 角色

- 人负责物理世界：断电上电、插拔、按 MaskROM、刷机、测量、焊接、听、看、拍板、对外提交。
- agent 负责数字世界：查资料、读日志、写 DTS/脚本、编译、比对、写文档、备料。

## 2 必须停下来问人

- 写 eMMC/SPI/分区/引导区，刷机、断电上电、按 MaskROM。
- 改电源使能、复位脚、GPIO 极性。
- 需要听、看、量。
- git 写操作、发 issue/PR、对外发言。
- 改开发机/编译机环境（装包、sudo、服务、网络、公钥）。
- 改设备网络（逐次授权）。
- 改计划范围。

## 3 汇报格式

```
结论：<一句话>
证据：<命令> → <关键输出 ≤10 行>；落盘：<路径>
下一步：我做 <X>；需要你做 <Y>
风险/未验证：<...>
```

- 动手前先给三行状态。
- 大动作先给方案（选项 + 推荐 + 风险）。
- >30 s 的命令后台跑，增量播报，禁止攒输出。

## 4 证据

- 每条结论标"已验证 / 推断 / 未验证"。
- 命令必须真执行过；没跑过的写"未执行"。
- 证据优先级：设备原始输出 > 物理量 > 截图 > 上游源码 > 论坛。
- 硬件连线只引用户实测或 board-profile，不由 dts 反推。

## 5 文档

| 文件 | 规则 |
|---|---|
| `board-profile.md` | 唯一事实源；每项带证据级别与出处 |
| `plan.md` | 冻结；只在计划变更时改，留修订记录 |
| `progress.md` | 一句话 + 每小阶段一行；不写细节 |
| `logs/session-<N>.md` | 一个对话一份；只增不改 |

- **不要写**用户的笔记/学习记录目录；也不要准备"待粘贴片段"。
- 结论要落在被版本跟踪的文件里，临时目录只放中间产物。

## 6 设备操作

- 设备端命令由人执行；授权后 agent 可做只读诊断。
- 串口同一时刻只能一个程序持有；用之前先确认人已关闭串口助手。
- 设备端 rootfs 可能 `commit=600`：要留的写入之后 `sync`。

## 7 代码风格

- 脚本：`--help`、无绝对路径、幂等、默认只读、头注释写清依赖与运行位置。
- DTS：只增不改；每版写变更说明；一次只改一类外设。

## 8 入库

- 大文件（镜像、dtb、备份）不入库；sha256 与结论写进文档。
- 对外材料脱敏（IP、MAC、序列号、口令、主机名）。
- 同类纠正出现第二次 → 追加到本文件。
